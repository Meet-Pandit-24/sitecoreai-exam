⚠ Exam-Critical Facts to Memorize
• Access Viewer → check user's effective rights on an item
• Sitecore CLI → required when source repo is NOT on GitHub / no out-of-the-box connector
• sitecore.json → Sitecore Developer Tooling configuration file
• Field exclusions for serialization → defined in .module.json or sitecore.json
• Scope property → SingleItem / ItemAndChildren / ItemAndDescendants / DescendantsOnly
• Default allowedPushOperations = CreateUpdateAndDelete
• Watch command (dotnet sitecore ser watch) → auto-syncs dev-managed nodes
• Provision step creates → CM, Editing Host, Experience Edge
• New device fields → Width, Visibility, Icon (NOT "responsive breakpoints")
• withDatasourceCheck() → wraps components, shows friendly message when datasource missing
• useSitecoreContext → JSS hook for edit-mode detection + current language
• Authorization error from Sitecore API → invalid API key header
• Default GraphQL pagination first = 10
• Changing grid system after site creation → breaks layout references
• Component not visible in Pages → Rendering definition item not created in CMS
• IStyling base template → added to rendering params template for Page Builder CSS styles
• sc_apikey header → REQUIRED for Experience Edge GraphQL Delivery API authentication
• Sitecore_GraphQL_ExposePlayground = true → enables GraphQL IDE/Playground
• Preview Context ID → for local dev with unpublished/draft content
• Headless variants → defined in TSX file with matching variant definitions in Content Editor
• Templates available in Edge → must be in /sitecore/templates/Project/[your-tenant]
• "Hidden items" checkbox (View tab) → reveals Layouts/Templates nodes in Content Editor
• Standard Values benefits → Insert Options, Default Field Values, Default Workflow, Default Presentation
• Server Component / SSR (Next.js App Router) → for rapidly changing data + SEO indexability
• Security Editor manageable rights → Read, Write, Create, Delete, Inheritance (Debug/Access are NOT real rights)

A. A template has not been established for the Content Editor.
B. A layout has not been assigned for the content tree in the Content Editor.
C. The "Hidden items" check box has been unselected on the View tab of the ribbon.  ✓ CORRECT
D. The Layouts and Templates folders need to be created by a developer.
Answer: C
Validation: VERIFIED. Layouts and Templates folders are flagged as Hidden in Sitecore by default. The 'Hidden items' checkbox on the View tab toggles their visibility. Even Admin users need this enabled to see them in the tree.
NEW: Security — Editor Permissions (5-option variant)
Q155. A developer is updating the security access rights for a new role in the Security Editor. Which of the following permissions are they able to manage? (Select all that apply.)
A. Debug
B. Inheritance  ✓ CORRECT
C. Write  ✓ CORRECT
D. Access
E. Read  ✓ CORRECT
Answer: B, C, E
Validation: VERIFIED via Sitecore Security Editor documentation. Manageable rights: Read, Write, Create, Delete, Rename, Admin + Inheritance. 'Debug' and 'Access' are NOT real Sitecore access rights — they are distractors. Both Dump1 and Dump2 agree on B, C, E for this 5-option variant.
